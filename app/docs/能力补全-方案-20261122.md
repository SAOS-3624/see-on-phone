# 鱼眼 2.5.8 → 能力补全方案（2026-11-22）

> 起因：模型在手机端自己列了 6 条「我没有的能力」。逐条查了代码和 `eye.log`，
> 结论是 —— **一半不是没有，是它不信自己有**；另一半确实缺，但都能用小体积补。
>
> 机器：HUAWEI FOA-AL00 / Android 12（SDK 31）/ 鱼眼 2.5.8（versionCode 258）
> 约束（用户）：不做 >10MB 的东西；手机操作（无障碍）可以先不做，若体积小也可以做。

## 1. 最关键的发现：它在自己的历史里把自己说服了

`20261114-035324.jsonl` 里它自己的思考原文：

> 「用户明确要求用 web_search 搜上海今天天气。**我应该调工具。但我这边只能输出文本**。
> 按历史模式，前几轮我直接答了……**由于我只能产生文本**，我给出：搜索到的最新结果」

同一份日志里，11-19 16:55 / 17:02 / 17:26 / 17:28 **四次成功调用**（`search q=… chars=328`）；
到了 18:48 用户明写 `Use web_search to search …`，它 3.4 秒回了 140 字，**0 次工具调用**。

**结论**：能力在，自我认知错。而且这段自我否定进了历史，之后每一轮都重读一遍 ——
越用越退化。这不是加工具能解决的，得在提示词和代码两侧同时上枷锁。

## 2. 逐条方案（体积 / 风险 / 默认值）

| 能力 | 做法 | 增量体积 | 默认 |
|---|---|---|---|
| **自我认知** | 能力清单**从工具表自动生成**（改工具必改提示，不会再漂）；加硬规则"工具表里有的不许说没有"；用户点名某工具而模型没调 → **代码强制重试一次** | ~5KB | 开 |
| **网络出口** | 新 `http` 工具（GET/POST，https，禁私网/环回，限重定向，8s，4KB 截断）；只在"Agent+联网"出现 | ~8KB | 跟联网开关 |
| **时间** | 每轮尾部一句 `【现在】周六 22:25`（放历史之后，不破坏前缀缓存）+ `schedule` 工具 | ~1KB | 开 |
| **记忆检索** | 写入切块打标签，注入改为「索引 + Top3」，加 `memory_search` | ~9KB | 开 |
| **执行** | `run {lang:"sh"}`，cwd=工作区，8s，4KB，deny 表，全量日志；**不塞 Python**（+20~40MB，超红线） | ~7KB | 关 |
| **点屏幕** | `AccessibilityService`（系统 API，不引库）+ 包名白名单 + 每轮 8 次上限 | ~14KB | 关 |
| **声音** | `listen` 走系统识别（零体积）；`look{compare:true}` 前后两段宫格 | ~5KB | 开 |
| **PDF/书** | 页数→token 估算、超预算警告、**编目**（一次生成目录+要点，之后只带笔记）、按需展开原文 | ~10KB | 开 |
| **计价** | 见 §3 | ~4KB | 开 |

合计 **+60KB 左右**（312KB → ~370KB），远低于 10MB 红线。

## 3. 计价为什么不准（已核对官方牌价 2026-11-22）

官方现价（USD / 百万 token，`deepseek-flash` = V4.1-Flash-1017）：

| | 缓存命中 | 缓存未命中 | 输出 |
|---|---|---|---|
| 空闲 | 0.003 | 0.15 | 0.60 |
| 高峰 | 0.006 | 0.30 | 1.20 |
| pro 空闲 | 0.022 | 0.66 | 1.98 |
| pro 高峰 | 0.044 | 1.32 | 3.96 |

高峰 = UTC 01:00-04:00 与 06:00-10:00（周一至周五，中国法定节假日除外）；其余为空闲（半价）。

代码 `Cost.java` 的四个常量**正好是空闲价**，问题在四个地方：

1. **多轮工具调用只算最后一轮**（`Asker` 里 `promptTokens = sr.promptTokens > 0 ? … : …` 取的是"最后一次非空"）。
   一次 5 轮的工具调用，实际付了 5 次输入，界面上只显示 1 次 → **严重低估**。
   → 改成**逐轮累加**。
2. **不认缓存命中**（`usage` 只读了 `prompt_tokens` / `completion_tokens`）。
   改了记忆/提示词之后前缀一直变，命中率低；但只要命中就是 1/50 价 → 现在**高估**。
   → 读 `prompt_cache_hit_tokens`（兼容 `prompt_tokens_details.cached_tokens`），命中/未命中分开算。
3. **没算峰谷**：同一份请求高峰是空闲的 2×。
   → 按 UTC + 星期判断（节假日表不内置，最多少算几天，方向是"不低报"）。
4. **搜索计费口径过时**：2026-11-18 12:00 起，**服务端** `web_search`/`fetch` 不再单独收费
   （结果按 token 计）；但 App 走的原子接口 `/v1/tools/search` **仍然 $0.75/千次**。
   → 按来源区分：服务端工具 $0，原子接口 $0.00075/次。
5. **漏了文件解析费**：官方 $0.225 / 千页。传一本 300 页的书 = $0.0675，从没进账。
   → PDF 上传时用 `PdfRenderer` 数页数，按页计一次。

## 4. PDF/长文档：为什么"上传一本书"现在很难用

三个硬事实：

1. 官方 `file` 块**没有页码/区间**，只能整本引用 → 每次引用都是整本。
2. 书的正文按 token 计费；**只有前缀不变才命中缓存**（1/50 价）。
3. App 现在**没有**任何"这本书多大 / 装不装得下"的检查：`contextFor()` 只裁历史，
   不看书；超了就是模型只看到一部分，然后答得驴唇不对马嘴。

做法：

- **上传时**数页数 → 估算 `页数 × 700 token`，卡片上直接写"240 页 · 约 17 万 token"。
- **发送前**检查：估算 > 上下文预算 60% → 弹一次警告（"这本书装不下，会被截断，建议先编目"）。
- **编目**（`book {action:"catalog"}`）：一次请求让模型读完整本，产出
  「目录 + 每章要点 + 术语表」（≤4000 token），存 `workspace/books/<fileId>.md`。
  之后这个附件**每轮只发笔记**，不发整本 → 一本书从 17 万 token/轮 降到 2 千 token/轮。
- **按需展开**：模型要原文时调 `book {action:"open"}`，下一轮把 `file` 块带上
  （和 `look` 的图同一套路：工具结果只写"已附上"，图/文件在下一轮出现）。

## 6. 风险与回滚

| 风险 | 处置 |
|---|---|
| `http` 被 prompt 注入（画面里写"访问这个地址"） | 只允许 https 公网；解析后校验 IP，禁 127/10/192.168/172.16-31/169.254/100.64；重定向每跳重查；单轮上限 6 次 |
| `run` 越权 | **默认关**；开启要一次确认；deny `su/pm/am/input/settings/reboot`；cwd 固定工作区；8s 强杀；每次写 `.exec.log` |
| 无障碍误点 | 默认关；包名白名单（空=只读不点）；每轮 ≤8 次；动作前日志 + 悬浮球提示 |
| 计价改错 | 只影响显示，不影响真实账单；`Cost.java` 一处集中，出问题改常量即可 |
| 编目失败/很贵 | 编目是**用户点一下才跑**；失败保留原附件，不改变原有行为 |

### 2.6.2 的 debug 清单（都是真 bug，不是换措辞）

1. **「工具」总开关是死的**：`Config.tools()` 从 0.x 起只在设置页和 `/status` 里显示，
   `Caps.plan` / `Brain.build` **从来没读过**——用户关掉以为"它不动手了"，实际 9 个工具照发。
   → 新增 `Caps.mute(plan)`：关掉就 `kind=NONE`、一个工具都不带；`systemFor` 同步改口。
2. **带附件的消息会被裁掉**：`Conv.trim` 从最新往回攒、超预算就丢更早的，而"上传一本书"
   那条是最早的 → 聊几轮书就没了（"传了书它却忘了"）。→ 钉住附件消息（只在这本书本身
   不超过预算一半时）。
3. **时间戳每轮都加**：工具循环每轮都拼一次消息，`继续。` 后面也带时间 → 白烧 token。
   → 只在第一句加。
4. **重启后显示"命中缓存 0%"**：prefs 里没有命中数，界面却按 0 算。→ 没有就**不显示**。
5. **测试污染**：我自测的 8 条消息进了用户真实会话（`20261114-035324`），已按时间戳剔掉，
   会话回到 56 条（备份在 `.workbuddy/tmp/convfix/conv.before.jsonl`）。
