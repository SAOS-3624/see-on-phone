# 鱼眼 App

> 手机上的 AI：会聊天，也会自己看世界。纯 Java、零三方库、无 Gradle，APK 约 220 KB。
>
> 构建方式见 [`docs/BUILD.md`](docs/BUILD.md)；电脑侧插件在仓库根目录。

## 一页架构

```
┌─────────────────────────────────────────────┐
│ MainActivity      会话页：消息流 / 输入栏 / 状态 │
│ CallActivity      通话页：实时预览 + 字幕      │
│ SettingsActivity  设置：分组卡片               │
│ ConvActivity      会话列表                     │
├─────────────────────────────────────────────┤
│ EyeService        前台服务：谁在什么时候该发生什么 │
│  ├ Asker          一轮的执行者：说→想→干活→再说  │
│  ├ Brain          只发字节：HTTP 流式 + 拆包    │
│  ├ Tools          look / tune / memory / files │
│  ├ Looker         借相机 → 采样 → 拼宫格（/look） │
│  └ CallStream     通话页：一个会话一条连续管线    │
├─────────────────────────────────────────────┤
│ Conv / ConvStore  上下文：预算裁剪 + 滚动摘要   │
│ Pipeline / Packer 切点 → 档位 → 行 DP → 拼图   │
│ HttpServer        127.0.0.1:4444（给电脑插件）  │
│ Drm / EdgeTts     在线音色（失败回落系统 TTS）   │
└─────────────────────────────────────────────┘
```

界面全是**代码拼 View**，没有 layout XML、没有 ViewModel、没有 DataBinding。
`Theme / Glyph / Anim` 是三个自写的小件：设计令牌、纯 Path 矢量图标、动效工具。

## 一次"看一眼"发生了什么

```
模型决定调 look
  └─ Tools → Looker.grab(seconds)
       ├─ camAcquire()            借相机（计数 +1，3 秒留手）
       ├─ 采样 2~5 秒（相机 12~15 fps → 240×320 打分）
       ├─ Pipeline.push()         逐帧算变化分 → 找镜头切点
       ├─ 封箱：按切点密度分档（1/1、1/4、1/9…）
       ├─ Packer.pack()           行 DP 装箱：动得多的给大格子
       ├─ Sheet.compose()         画成一张 471×628 的宫格 JPEG
       ├─ Tokens.fit()            算这张图要花多少 token
       └─ camRelease()            还相机
  └─ 一张 base64 JPEG 回到模型
```

一条宫格 ≈ **197 token**，4~7 KB。它**会留在会话历史里每轮重发** ——
所以只在真要"看"的时候调，别轮询。

## 通话页：一条连续管线 → 一张一张宫格

和 `dsh-see-now` **同一套算法、同一个形状**：**一个通话会话 = 一条 `Pipeline`**
（`CallStream`），相机按 5fps 逐帧喂进去，由管线自己按
`flushGain`（再塞就碎格）/ `maxWaitSec`（= 发送间隔）/ `maxFrames:40`（保险）封箱。
App 只做两件事：把封好的那一箱取走发出去、把正在攒的那一箱画成预览。

> 1.1.x 的老写法是"每次要发图，把最近 N 秒的帧重喂一遍新管线"。看着像 see-now，
> 其实把 `gapEwma / Tiers / 跨帧去重 / 积分累积` 每窗清零了 ——
> 出来必然"只有切点、一窗两帧、整窗一样大"。现在这些状态跨箱累积。

| 灵敏度 | 发送间隔（= 时间封箱线） | 采样 | 静止画面兜底 |
|---|---|---|---|
| 平静 | 25s | 5fps / 200ms | 20s 一帧 |
| 正常 | 15s | 5fps | 20s 一帧 |
| 灵敏 | 8s | 5fps | 20s 一帧 |
| 游戏 | 20s | 5fps | 40s 一帧 |

灵敏度同时改"切点门槛"和"发送节奏"，两者不会脱节。静止画面多久出一帧就是 see-now 的
`silentFloorSec` 原值（20 秒），不另发明"窗口/4"那种换算。

> 为什么是 5fps 而不是相机的 15fps：15 秒全留是 225 张 JPEG（11MB），打分也要 1.5 秒；
> 切点判据吃的是相邻**采样帧**的差分，采样越稀差值越大，反而更好判。

**拼图口径**（和电脑版一致）：

- 画布 471×628（3:4），格子保持 3:4 ⇒ 一格都不裁（`maxCrop: 0`）；
- 档位 1..8 由 `Tiers` 按**出帧密度**算（`tierMode: density`，see-now 的原生默认），
  切点帧格子大、兜底帧格子小；换 `weight` 才是"按变化量分面积"；
- 一张放不下时**整体缩一档**重排（宁可格子小，也不拆成两张、不丢帧）；
- 一张图放几帧**不是设置项**：由"装不下 / 碎格 / 时间到"判，`maxFrames: 40` 只是防爆保险。

| 自动 | 行为 |
|---|---|
| **开** | 每个发送间隔（8~25s，跟灵敏度走）交一次，它自己看一眼、有话说就说一句 |
| **关** | 一个字节都不发。等你打字或说话时，把当前这一箱拼成一张宫格**挂在你的话上**一起发 —— 回答的是你现在看到的 |

**攒批**（设置 · 通话 · 攒批，`wakeBatch` 1~4，默认 1）：攒够几张宫格才一起交给模型。
省的不是图的钱（一张 798×450 才 222 token），省的是**每一轮都要把整个上下文重过一遍**那笔 ——
所以"队列能压几张"和"一次交几张"必须是同一个数（`queueDepth` / `ready()` / `takeMany()`）；
光攒不交是不省的。

> 改攒批要**重开通话页**才生效（队列深度在建管线时定）。默认 1 = 一箱一交，和以前完全一样。

顶部胶囊显示 `在看 · 自动 · 开`；左下角是**拼好的那张图本身**，标题行 `宫格 · 5.7s · 3 格`
（编号和格子和真发出去的一模一样 —— 它由 `CallStream.preview()` 算，走的是同一个
`CallSheet.layout`，所以"预览长什么样 = 发出去什么样"）。右侧「隐藏」能关掉，
关掉之后**连拼图都不算**。

> 预览是**每抓一帧重排一次**（5fps ⇒ 200ms 一张，拼图 + 编码实测约 10ms）。
> 静止画面时最后一帧没变就跳过重拼，不空转。
>
> 相机刚开的 1.2 秒（`WARMUP_MS`）收到的是黑帧，一律不要 —— 不然第一格是纯黑。

**发出去不清状态**：`resetDraft` 只清"正在攒的这一箱"，去重基准、档位密度、`gapEwma` 全部保留。
所以自动发完你紧接着开口，拿到的还是紧接着的这几秒，不会缩成 2 帧。

改这块之前先跑离线探针（不装手机也能验）：

```bash
bash tools/parity/grid.sh      # 混档版面：N 帧 = N 格、只出一张、格子 3:4
bash tools/parity/capture.sh   # 采样节奏（5fps 闸门 + 预热期）
bash tools/parity/stream.sh    # 合成素材：静止 / 平移 / 硬切 → 出几帧、几档、什么理由；外加攒批
bash tools/parity/render.sh    # 真画成 PNG 放到 tools/parity/out/，用眼睛验版面
```

两个坑（都踩过）：

- **不能只喂几张稀疏快照**：切点判据吃相邻帧差分，跨几秒的快照判不出切点，
  出来就是"每格一个不相干的画面"（1.0.1~1.0.3 的病）。
- **"把阈值全设 0 让它别筛"是反效果**：`decide()` 的 keep 条件是
  `mcCut || (s>=cutAbs && (spike||step)) || isolated`，四个阈值清零后只剩 `spike` 成立，
  平缓变化的帧全丢 —— 真机日志固定 `fed=3 frames=2`。

## 相机是"借来的"

界面**从不申请相机**。只有两种情况会 `open`：

1. 模型调用 `look`（或电脑插件打 `/frame.jpg`、`/video/mjpeg`、`/look`）；
2. 你手动进入通话页。

有引用计数 + 3 秒留手：最后一个用户走了 3 秒后才真正 `close`，
这样连续两次 `look` 不会反复开关相机（华为上重开一次要 600ms 左右）。
**改这套之前先想清楚**：搞错了相机会被永久占用，别的 App 就打不开了。

## 工作区（它能自己写文件）

它有一块地：`Download/DSH-Go/workspace/`。说"帮我记下来""存成文件"，它就写进去 ——
你在文件管理器里**能直接看到、能拷走、能删**。

| 工具 | 作用 |
|---|---|
| `files({action:"list"})` | 列目录（名字、大小、是不是目录） |
| `files({action:"read", path})` | 读文本（超 64 KB 截断并告诉它还剩多少） |
| `files({action:"write", path, text})` | 整篇覆盖 |
| `files({action:"append", path, text})` | 追加 |
| `files({action:"delete", path})` | 删一个文件（目录非空不给删） |

**边界只有这一个目录。** Android 11+ 的分区存储下，普通应用全盘写要么用
`MANAGE_EXTERNAL_STORAGE`（商店会拒），要么让用户一个个目录授权。而真实需求是
"把我说的东西存下来" —— 一块固定的地就够，还不需要任何额外权限。

三道防线防越界：拒绝对路径 → 拒绝任何 `..` 段 → 解析完再确认 `canonicalPath` 还在根里
（第三道才真正管用，前两道只是让报错好懂）。一次写上限 512 KB、读上限 64 KB。

> 和 `memory_write` 的分工：**以后每轮都要自动看到**的 → 记忆；**存下来给我用的** → 工作区。

## HTTP：电脑把手机当眼睛

端口固定 `4444`，**只绑 `127.0.0.1`**。从电脑访问要 `adb forward tcp:14444 tcp:4444`。

| 端点 | 作用 |
|---|---|
| `GET /status` | 版本 / 相机是否开着 / 思考档 / 当前会话 / 记忆条数 |
| `GET /frame.jpg` | 单帧 JPEG（按需开相机，≤1.5s） |
| `GET /video/mjpeg` | MJPEG 流（连着才开相机，断开 3 秒关） |
| `GET /look?seconds=` | **现场拼一张宫格**，返回 `{images:[b64], frames, tokens, why, canvas}` |
| `GET /say?text=` | 朗读 |
| `GET /ask?text=` | 让手机当场回答（走完整工具循环） |
| `GET /config?key=&model=&think=` | 改接口 / 模型 / 思考档 |
| `GET /?peek=1` | 排障：把所有配置键原样吐出来 |

`/video/mjpeg` 和 `/frame.jpg` 的语义刻意与 IP Camera 那类 App 对齐 ——
所以第三方客户端也能直接连它。

## 会话与记忆

- 会话落成 **一行一条的 jsonl**（`filesDir/conv/<id>.jsonl`），出错拿记事本就能看；
- 上下文预算可调（2k~900k），超了先裁旧消息、图片单独 offload、再不行滚动摘要；
- 记忆是纯文本文件，每轮自动进 prompt；设置页能单条删；
- 和桌面互通只交换**最笨的东西**：jsonl + 纯文本 + 一堆 jpg，`adb pull` 一个目录就完事。

## 已知限制

- **`minSdk 21` / `targetSdk 29`**：见 [BUILD.md](docs/BUILD.md) 的说明，不是懒得升级。
- **语音输入只有单句**（系统 `RecognizerIntent`）。常驻 `SpeechRecognizer` 在部分机型上
  会一直 `ERROR_RECOGNIZER_BUSY`，试过了，不划算。
- **在线音色是逆向接口**：`Sec-MS-GEC` 令牌五分钟一格，服务端会校验。
  它随时可能被改掉，所以**必须可关**（选"系统默认"就完全不走网络）。
- **导盲模式不是辅具。** 见 [../NOTICE](../NOTICE)。
